# TRG-2026-0001：日志检索接口的全量扫描导致 CPU 随历史累积漂移

> 编号是自签的，不是官方分配的 CVE。写法参照 CVE 记录，目的是把「修好」变成可反驳的判据。

## 基本信息

- 组件：`dissipation-locator` 靶场，`GET /search`
- 受影响版本：缺陷版（默认）
- 修复版本：`--fixed`（第二版，见下）
- 类型：CWE-400 资源消耗 / 算法复杂度
- 发现方式：长跑观测三通道耗散，`E_int = 81.09`，`E_total_z = 138.24`

## 根因

每次请求把当前查询追加进 `history`，然后遍历整个历史：

```python
for item in history:
    total += len(item)
    if prefix and item.startswith(prefix):
        total += 1
```

单次复杂度 O(n)，n 是历史长度。历史只增不减，所以同样一次请求的 CPU 随运行时间上升。短跑时 n 小，测不出来。

## 触发

持续向 `/search` 发请求即可，不需要特殊载荷。速率 100 次/秒，60 秒后每请求 CPU 从约 265µs 涨到约 405µs。

## 第一版修复（已证伪）

把 O(n) 扫描改成只维护 `total_len`：

```python
self.m.total_len += len(q)
result = self.m.total_len
```

CPU 复杂度变成 O(1)，长跑 `E_int = 0`。

## 验收判据

| 判据 | 通过条件 | 量法 |
|---|---|---|
| G1 功能等价 | 同一查询序列，修复前后每次返回值一致 | 300 次请求逐条比对 |
| G2 CPU 不漂移 | 8s 预热后 16s 内，末两窗 CPU/请求 ÷ 首两窗 ≤ 1.2 | 每 4s 聚块，200 次/秒 |
| G3 内存有界 | 10000 次请求后 RSS 增长 ≤ 2048KB | `/metrics` 前后差值 |
| G4 尾延迟 | 2000 次请求 P99 ≤ 50ms | 客户端逐次计时 |
| G5 长跑等价短跑 | 10s 预热后 180s 内，末三窗 CPU/请求 ÷ 首三窗 ≤ 1.2 | 每 4s 聚块，100 次/秒 |

G5 是算法判据。缺陷的根因是「每请求代价随历史长度增长」，所以修好不能只是把曲线压平一时，而是要让第 180 秒的单次代价与第 12 秒相同。加超时、加限流、加缓存都可能让 G2 变绿，但只有改变聚合方式才能让 G5 成立。

## 攻击与结果

```
python3 cve/attack.py --label v1 --v1 --long   # 第一版修复
python3 cve/attack.py --label v2 --long        # 第二版修复
```

| 判据 | 第一版 | 第二版 |
|---|---|---|
| G1 功能等价 | FAIL，300/300 不一致 | PASS，0/300 |
| G2 CPU 不漂移 | PASS，0.992 | PASS，1.040 |
| G3 内存有界 | PASS，+12KB | PASS，0KB |
| G4 尾延迟 | PASS，0.201ms | PASS，0.194ms |
| G5 长跑等价短跑 | PASS，1.053 | PASS，0.964 |
| 总判定 | **漏洞没修完** | 全部通过 |

第一版失败的原因不是性能，是语义：缺陷版返回「历史总长度 + 首字符匹配数」，第一版只返回总长度。CPU 指标全绿，功能已经变了。这是典型的「修一个洞，长一个洞」。

## 第二版修复

保留 O(1)，同时补回首字符计数：

```python
self.m.total_len += len(q)
prefix = q[:1]
if prefix:
    self.m.first_counts[prefix] += 1
    result = self.m.total_len + self.m.first_counts[prefix]
else:
    result = self.m.total_len
```

这相当于把「按首字符分组计数」做成增量聚合，结果与全量扫描逐条一致。180 秒 45 个窗口，末三窗/首三窗 = 0.964，长跑后段与短跑前段同价——长运行被拆成了可重复的短运行。

## 这份记录不能保证什么

- 只覆盖搜索接口的五条判据，不覆盖突发队列、并发竞态、跨接口组合
- 不覆盖长时间内存碎片与分配器行为
- 「保证」只在判据表覆盖的范围内成立；范围外只能靠持续回归与多人复核
- G2/G5 的 1.2 倍阈值是工程取值，不是统计显著性检验
